# FitLog ビジョン議論 指示書（AIに渡す用）

この議論を別のAI・別のセッションで再開するとき、このファイルを最初に渡す。

---

## 1. この議論の目的

FitLog を「作者本人の記録アプリ」から先へ進めるために、**長期のビジョンを決める**。
機能の話（次に何を作るか）ではなく、その手前の話をする。

決めたいこと：

1. **誰のためのアプリにするか** — 自分専用 / 身近な数人に配る / 不特定多数
2. **AIに何をさせるか** — 週次レポート / 毎日の声かけ / メニュー生成 / 分析は手動のまま
3. **「目標を宣言する習慣」を誰に向けたものにするか** — AI相手 / 人間相手
4. **上の答えを踏まえて、いま決めておくべき設計** — 特に「後から変えられないもの」

## 2. 前提（FitLogの現状・2026-09時点）

- Android ネイティブ（Kotlin + Jetpack Compose + Room）。ソースは `app/src/main`。
- 記録できるもの：体重・体組成 / 筋トレ（種目＋セット単位）/ ランニング（GPS経路・スプリットあり）/ 食事（カロリー・PFC）。
- 長期目標・週次計画のテーブル（`goal` / `weekly_plan` / `weekly_strength_target`）がある。
  中身は `/weekly-plan` スキルが追記する（`PlanSeeds.kt`）。
- データは**端末内のみ**。外部送信・同期・ログインなし（`要件定義書_FitLog.md` 4章）。
- AI分析は要件定義では**スコープ外**。「JSONに書き出してAIに渡せる形にするところまで」が現行の線。
- 実データが入って毎日使われている。**やり直しのきかない変更を入れない**のが最優先（`CLAUDE.md`）。

### データ設計の思想（ここが資産）

`CLAUDE.md` より。この3分類を崩さない。

| 種別 | 意味 | 実体 |
|---|---|---|
| 種目（exercise） | 「それがどういうものか」（オブジェクト） | `exercise` テーブル・`description` |
| 記録（strength / running / meal / weight） | 「いつ・何を・どれだけ」（出来事） | 各テーブル |
| メモ（`strength.memo`） | 「その回どう感じたか」（主観） | 記録に付随 |

一般的な記録アプリは「出来事」しか持たない。FitLogは**主観と定義を持っている**ので、
AIに渡したときに数字以上のことが言える。ビジョンはこの強みを軸に立てる。

## 3. 進め方

- **作者は音声入力で話す。** 文字起こしが崩れることがある前提で読むこと。
  崩れていたら、勝手に解釈を進めず「こう受け取ったが合っているか」を先に確認する。
- **一度に一問だけ聞く。** 質問を並べない（歩きながら話しているため）。
- 一般論で終わらせず、**自分の意見と推す理由を先に言う**。判断は作者がする。
- 作者はIT業界1年目。専門用語は使ってよいが、初出のときは一行で意味を添える。
- 「取り返しがつくか / つかないか」を判断軸として毎回明示する。
  （例：アカウントと同期は一度入れると抜けない ／ AIの使い方は後から差し替えが効く）
