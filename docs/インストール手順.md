# FitLog をスマホに入れる

FitLog は Google Play ストアには出していない。GitHub Actions が作ったAPKを、
スマホに直接入れて（サイドロードして）使う。

そのため、初回や更新のたびに Android 側が一度止めにくる。**これは故障ではなく、
Playストアを通していないアプリに対して必ず出る確認**なので、進め方さえ分かっていれば入る。

## 1. ダウンロードする

- **いつもの最新版（mainの内容）**:
  [リリースの「最新ビルド」](https://github.com/warewarehautyuujinnda-code/AllFit/releases/tag/latest)
  を開いて `fitlog.apk` をタップする。
- **マージ前のブランチを試したいとき**: そのブランチの Actions の実行を開き、
  下の方の Artifacts から `fitlog-<ブランチ名>` をダウンロードする。
  こちらはZIPなので、解凍してから中のAPKを開く。

## 2. 「アプリがインストールされていません」と出たとき

だいたい原因は次の3つ。上から順に確認する。

### ケースA: Play プロテクトにブロックされた（いちばん多い）

> **Google Play プロテクト**
> デバイスを保護するため、アプリをブロックしました
> このデベロッパーのアプリは Play プロテクトにスキャンされたことがありません。

このダイアログで、大きく表示されている **「OK」を押すとインストールが中断される**。
中断された結果として、そのあとに「アプリがインストールされていません」が出る。

正しい進め方は、**「OK」の少し上にある小さな文字の「インストールする」を押す**こと。
目立たないが、これがインストールを続行するボタン。

### ケースB: 前に入れた版と署名が違う

以前に Android Studio から手元でビルドして入れた版が残っていると、鍵が違うため
上書きインストールが拒否される。この場合は Play プロテクトの警告を通過しても入らない。

1. アプリを開き、**データタブ → 「JSONで書き出す」** で記録を保存しておく
   （アンインストールすると端末内の記録は消える）。
2. FitLog をアンインストールする。
3. あらためてAPKを開いてインストールする。
4. **データタブ → 「JSONから読み込む」** で記録を戻す。

CI と手元のビルドはどちらも `keystore/debug.keystore` の共有鍵で署名しているので、
一度この鍵の版に揃えてしまえば、以後は上書きインストールできる。

### ケースC: 「不明なアプリのインストール」が許可されていない

APKを開いたアプリ（Chrome、Files、ドライブなど）ごとに許可が要る。
案内に従って設定画面に飛び、そのアプリに対してインストールを許可する。

## 3. ちゃんと入れ替わったか確かめる

アプリを開いて **データタブをいちばん下までスクロール**すると、バージョンが出ている。

```
バージョン
1.0 (build 42 / a1b2c3d)
```

`build` の番号が GitHub Actions の実行番号、うしろがコミット。
これが変わっていれば新しい版に入れ替わっている。手元でビルドしたものは `1.0 (local)`。

## なぜ debug ではなく release ビルドを配っているのか

debug ビルドはマニフェストに `android:debuggable="true"` が付く。この状態のAPKは
Play プロテクトがサイドロードを強くブロックする条件に当てはまるうえ、デバッグ用の
ツールを同梱するぶんサイズも大きい。そのため配布用は release ビルドにしている。

ただし署名鍵は debug と同じ `keystore/debug.keystore` のままにしてある。
鍵を変えると今入っているアプリに上書きできなくなる（ケースB）ため、あえて揃えている。
この鍵は公開リポジトリに入っているのでひみつではない。Playストアに出すことになったら、
GitHub Secrets から読む専用の鍵に差し替えること。
